1. Problem Statement
Building GTI Integrations in a target product involves analysing and understanding a new platform and feasibility check of third party development that is slow, inconsistent, and relies entirely on individual memory/capabilities.
2. Current Workflow (Manual)
1. Gather product information and understand its end-user workflows, features, and primary use cases.
2. Identify product features that can leverage GTI capabilities or be enhanced through GTI integrations.
3. Verify whether the product supports external integrations/plugins and check for an official marketplace or installation mechanism for end users.
4. Search for publicly available documentation, SDKs, APIs, or developer guides required for third-party integration development.
5. If public development resources are unavailable, check for partner programs or vendor-supported integration models. If required, initiate communication with the team for further integration details and enablement.
6. Analyze the publishing and deployment process for the developed integration, if supported by the platform.
7. Prepare a feasibility and integration analysis document covering all collected findings and recommendations.
3. Proposed Solution
3.1 Broader Design


An AI agent that takes a product name as input and produces a complete, near-final integration proposal draft with feasibility as output, grounded in the team's own institutional knowledge, past decisions, and GTI's current capability surface.        
Context Engine
This serves as the centralized repository for GTI integration knowledge built using Kapa.ai. The knowledge base is further divided into 3 categories.
1. GTI Capabilities & APIs
* This set of corpus represents all the GTI capabilities along with the APIs available to utilize those capabilities.
2. Integration Proposals
* This set of corpus includes all the Integration Proposals along with their approved or rejected status and supporting rejection reasons and limitations
3. Integration Knowledge
* This set of corpus represents the GTI Integrations that have been either released or are currently being implemented by the team.
All this information available is converted into structured markdown files before being loaded into the knowledge base.Compiling the content into markdown will help improve indexing, semantic search accuracy, and contextual retrieval within the RAG pipeline.
The overall workflow consists of the following modules:
* Platform Research Module
The workflow starts when a user provides the name of a target platform or product. This module performs external research using web search APIs and gathers publicly available information such as platform capabilities, APIs, authentication methods, supported integrations, SDKs, webhook/event support, and developer documentation. The output of this module is a refined platform profile that summarizes the key technical details required for integration analysis.
* Platform Profile Module
Once the external platform profile is prepared, this module queries the Kapa AI knowledge base to retrieve relevant GTI context. Using semantic search, it will help identify matching GTI capabilities, APIs, similar integrations already built, related architectural patterns, and historical proposals that will help accelerate the implementation. 
* Prompt Assembler Module
This module combines the external platform research with the retrieved internal GTI knowledge into a structured prompt for the LLM. The prompt is organized to provide both business and technical context, enabling the LLM to generate more accurate and relevant outputs.
* Proposal Generation (LLM Output)
The assembled prompt is passed to the LLM, which will generate a draft integration proposal document. The proposal will include:
   * Integration overview and feasibility
   * Suggested integration approach
   * Relevant GTI capabilities and APIs
   * Reusable components or existing patterns
   * Authentication and data flow 
   * Risks, dependencies, and assumptions
   * Recommended next steps for implementation

5. Testing Strategy


Testing Strategy:


   * Retrieval quality
   * Minimum 70% of top-5 results rated relevant or partially relevant per corpus. No individual corpus below 60%.
   * Agent correctness
   * Agent tested against 10 real product names spanning SIEM, SOAR, EDR, and email gateway categories. 
   * Output quality
   * Team review of generated proposals scores at least 7/10 average across: use case relevance, endpoint accuracy, SOC journey narrative quality, and proposal structure adherence. 
   * Reliability 
   * Agent produces output for 100% of test inputs - no crashes, no empty outputs, no hallucinated endpoints. Prompt version committed to repo with evaluation scores attached.
   * Groundedness
   * All GTI endpoint names and rate limits in generated proposals are traceable to Corpus A. No API detail in any output that is absent from the knowledge base.






Exit Criteria:


   * Use this tool for all the next set of proposals to be prepared for GTI integrations.
   * It should reduce the time spent by almost 80-90% on proposal and feasibility analysis.




6. Enhancements and Reusability
   * AI Agent’s GTI and Integrations context can help us generate boiler code and speed up the implementation.
   * AI Agent can be further extended to crawl new GTI features and suggest enhancements within the existing integrations as well as help explore the next set of products to scope.
   * Reusability:
   * The prepared context engine/knowledge base workflow can be reused for preparing similar KB for other products like GTI.
   * This agent workflow can be used for preparing similar feasibility/proposal documents for security products and new customers.
